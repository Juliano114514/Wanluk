# 韵录：单机方言采集助手

面向汉语方言田调。发音人使用引导模式自录，研究者在本机编辑调查包。通用题目与汉语音韵标注分离，为后续语言扩展保留空间。

当前代码接入了下述单机链路；录音、迁移和文件交换仍需按文末清单进行真机验收。未接入服务器、链接领取、账号、录音上传或云同步。

## 使用流程

1. 首页选择“开始录制”，再选择调查包，或通过系统文件选择器导入任务 JSON。“管理员”入口用于调查包和字库管理。
2. 称呼与方言均为选填，默认记在本机、不重复询问；后续可在准备录制时修改，也可从“管理员 → 右上角齿轮 → 设置 → 录制者信息”修改。点击“开始吧”确认已了解用途并同意录制。
3. 录制页以整页大字卡为主，字库单字题的已有组词提示居中显示；底部提供上一个、播放、录制、重新录制、下一个和“我不会念”。正式录音及重录默认长按开始、松手停止，可在“管理员 → 设置 → 录音方式”切换为点击开始、再次点击停止。试音、进度、备注、历史与导出位于“更多”。
4. 从“开始录制 → 我的录制”继续；题目位置和已完成进度存入 Room。
5. 末项点击“结束”保存进度并提示“是否导出？”，可选择“立即导出”或“以后再说”。“我的录制”条目菜单也可导出成果 ZIP，未完成的录制同样支持；无有效录音时前置提示导出失败。文件写入系统文件选择器指定的位置，再自行转交研究者。

预设“家乡话录制体验 · 30 项”只演示工作流程，未经具体方言研究设计审定，不代表完整音韵覆盖。

## 研究者的本地编辑

- “新建调查包”直接进入字目网格，点选后按“选好了”，最后命名并保存；取消命名可继续选字。
- 管理页点卡片进入编辑，复制和导出放在卡片“更多”；编辑页的说明、语言、方言、预览与 JSON 放在“更多”。
- 字库支持搜索、已选筛选和长按详情；摄、罕度与单字／词语切换放在“筛选”。同字不同音的字目独立保留。
- 添加单字、词语或句子，调整顺序、提示、每题 1–5 次重复和是否允许跳过。
- 预览发音人提示，或通过高级 JSON 编辑器修改协议允许的字段。
- 保存生成新版本；已有录制会话使用完整任务快照，后续编辑不会改写旧任务。
- 相同 packageId / revision 的导入内容必须一致，否则拒绝覆盖。

任务包最多 500 题，包含重复次数后最多 1500 个步骤。当前只支持文本题目，不支持图片、音频提示、脚本、条件分支或任意网络资源。

## 调查包协议 v1

- JSON Schema：[docs/survey-package.schema.json](docs/survey-package.schema.json)
- 示例：[foundation/src/main/assets/surveys/starter-zh.json](foundation/src/main/assets/surveys/starter-zh.json)
- schemaVersion 表示协议版本，packageId + revision 表示任务内容版本。
- itemId 是稳定题目身份；text 是实际采集文本，instruction 是操作提示，type 明确单字、词语、句子。
- phonology 是可选的汉语音韵标注。其他语言或无传统音韵坐标的题目无需填写。
- recordingProfile 固定为 wav-pcm16-48000-mono，不支持静默改变采集预设。

导入要求 UTF-8（可带 BOM）、最大 2 MiB。应用显式校验类型、长度、版本、ID 唯一性、总步骤数；拒绝重复 JSON 字段、过深嵌套、不支持的题型和字段。JSON Schema 描述结构，跨题目数量总和等限制由应用补充校验。任务内容仅作数据解释，不执行表达式或代码。

## 录音与恢复

- AudioRecord 采集 PCM，原始文件为 WAV / 48 kHz / 16-bit / 单声道。
- 检查设备对 UNPROCESSED 音源的支持；不支持时明确使用 VOICE_RECOGNITION，并记录实际选用音源与路由设备描述。
- 不支持指定采样格式时明确报错，不静默降采样。实际设备处理行为和科研适用性需要实测。
- 单条正式录音最长 120 秒，试音最长 15 秒；录前检查可用存储空间。
- 长按录音在松手、手势取消或控件离开界面时请求停止；首次授权麦克风后需重新长按，不在授权回调中自动开始长按录音。试音仍通过明确点击开始，辅助功能也保留点击启停入口。
- 录制期间显示电平、保持屏幕唤醒；声音过小、可能削波、过短、设备路由变化会给出提示。这些提示不等于研究质量认证。
- 录音先写独立 .part 文件，完成 WAV 头和数据同步后才成为 .wav；数据库成功保存后才替换本条采用版本。
- 保留全部成功的重录版本，可回听并重新采用旧版本。
- 切后台会请求结束本条并保存；没有前台服务，不承诺锁屏或后台持续录音。
- 进程被杀后，未完成的录音尝试标为中断，不计入完成；上一次成功录音不变。中断 .part 文件及极端中断时的未关联文件可能留在应用目录，不作为有效音频导出。
- 备注可手动保存，在切换题目、离开会话、开始录音和正常退后台时也尝试保存；强制杀进程前未落库的编辑不能保证恢复。

## 两种导出文件

### 调查任务包（JSON）

只包含题目、说明、规则和标注。通过系统文件选择器保存，可主动打开系统分享面板。另一台装有韵录的设备可从“开始录制”或“管理员”页面导入。

也可以在管理员的调查包卡片“更多 → 分享二维码”离线分享。另一台设备从“更多 → 二维码导入”打开相机扫描，或从收到的图片识别；识别完成后预览名称、题目数量并确认导入。二维码只含方案，不含录制者信息和录音。

- 使用无损压缩；小方案一张二维码，大方案分为多张，最多 32 张。逐张扫描或保存图片，支持乱序与重复扫描；内容过大时提示改用 JSON 文件，不删减题目或标注。
- 整组 SHA-256 校验完整性，不代表来源可信；沿用 JSON 协议 v1 的严格校验及同 ID / 版本冲突规则。
- 解压后仍限制为 2 MiB，图片输入限制为 12 MiB 并缩采样解码。相机只在用户主动扫描时申请权限，也可不授予权限而直接识别图片。
- 扫码进度在当前页面及旋转重建时保留；关闭导入或进程退出后需要重新收集。已有方案和录音不受影响。

### 录制成果包（ZIP）

| 文件 | 内容 |
|---|---|
| task.json | 本次录制的完整任务快照 |
| metadata.csv | 每个步骤、当前采用录音、录音参数、状态、备注和跳过原因 |
| session.json | 会话信息及所有录音尝试，包括未采用版本和中断状态 |
| audio/*.wav | 全部成功保存的原始录音，包括旧版本 |
| sha256.json | 导出音频文件的 SHA-256 |
| README.txt | 字段和使用说明 |

- 可导出尚未完成的任务，pending / skipped / recorded 分别表示待录、主动跳过、已有采用录音。
- 试音及中断片段不导出。音频文件使用会话 UUID 和录音 UUID 定位，不使用字词文本拼接本地路径。
- CSV 使用 UTF-8 BOM、标准字段转义，并对潜在表格公式文本加单引号；JSON 保留原文本。
- ZIP 流式写入所选文档。失败时不标记导出成功，本地原始录音保留；目标目录可能留下不完整文件，需要删除后重试。
- 导出包含发音人代号、方言背景、声音和备注。界面会确认范围，不自动上传或发送。

当前成果包用于人工交接与 Praat 分析，不提供成果 ZIP 自动恢复到另一台韵录的功能。

## 字库与数据迁移

当前内置 WordCaseList.csv 为 UTF-8 BOM、13 列、10292 个数据行。其中来源 ID 6357 没有字目，导入时跳过，因此有效条目为 10291；有组词的行数为 8754。

表头：id,聲,呼,等,韻,調,組,攝,單字,多音,组词,原註,罕度

- 续行继承上一条音韵坐标；同字不同读音或义项保留独立记录。
- 内置资产按 SHA-256 检查更新，不再使用“数量不同就清空重导”。
- 稳定来源 ID 采用 builtin:wordcase:<CSV id>；维护 CSV 时不得重排或复用已有来源 ID。
- v2 升级时按完整内容匹配旧记录，保留其数据库 ID；相同内容的多条记录逐条匹配。
- 字库更新在事务内完成，按来源 ID 更新或新增，保留用户条目和未匹配的旧条目，不主动清理旧字。
- 等的空白或 - 在旧字库中仍保留原有 0 语义；生成任务标注时转换为 null，不伪造音韵分类。
- Room v3 增加调查包、会话、步骤、录音和内置资产版本表；保留 v1→v2→v3 迁移链，启用 schema 导出。
- 同名同音的条目不能按字符去重；调查任务持有题目快照，不依赖本地字库自增 ID。

## 工程边界

| 模块 | 职责 |
|---|---|
| app | Compose 页面、ViewModel、权限与系统文档选择器 |
| foundation | 通用任务协议、校验、导出模型、录音路径及内置资产 |
| lib-room | 字库、任务、会话及录音元数据，迁移与 Repository |
| lib-record | WAV 采集与本地回听 |
| lib-record-ui | 点击／长按录音控件与手势收尾，不依赖录音引擎、数据库或设置存储 |
| lib-export | ZIP / CSV / JSON 成果导出 |
| lib-compose-ui | 共用矢量图标，保留对应可编辑 SVG 源文件 |
| lib-settings | 本机录制者信息、是否重复询问、录音方式及持久化状态 |
| lib-settings-ui | 条目式设置页及复用的录制者信息表单，依赖 lib-settings，不依赖 app 或 Room |
| lib-survey-transfer | 离线二维码分片协议、完整性校验、图片编解码及相机扫描适配 |

沿用 UI → ViewModel → Repository / 服务的方向，录制与方案交换使用独立 ViewModel。设置模块不依赖数据库；交换模块依赖 foundation 协议，不依赖 app 或 Room，由 app 确认后调用 Repository 入库。复用现有 Gson、Room、Koin 和协程；二维码模块独立封装 ZXing Core 3.5.4 与 ZXing Android Embedded 4.3.0，版本锁定于版本目录。

Android minSdk 24，compile / targetSdk 36。applicationId 为 com.wanluk.app，源码包为 com.wanluk。录音保存在应用内部专属目录 files/recordings，任务和进度存于 Room。卸载或清除应用数据会丢失未导出的材料。禁用系统自动云备份与设备迁移；不申请网络或 broad storage 权限。

旧字例 demo 源码保留用于参考，应用启动入口已切换到 StudioApp。

1. 旧版数据库升级，重启后字库 ID、已有记录和计数稳定。
2. 创建任务、按字库选题、JSON 导入导出；非法和不兼容任务被明确拒绝。
3. 修改调查包后旧会话仍显示原题目；同字不同音和重复录制分别对应正确录音。
4. 首次拒绝麦克风权限、永久拒绝后从设置恢复、输入设备变化。
5. 试音、正式 WAV、回听、连续重录、采用旧版、跳过与备注保存。

7. 空间不足、文档提供方不可写、导出中断；不能丢失本地成功录音。
8. 将成果带到电脑，对照 metadata.csv，在 Praat 中检查时长、声道、音频参数和实际波形。
9. 留空称呼与方言进入录制；重启后记忆仍在；取消“不重复提问”后再次显示字段，修改资料不改写旧会话。
10. 二维码单张与多张跨设备扫描、图片识别、乱序及重复扫描；拒绝其他方案混入、不完整内容和同版本冲突；相机拒权时可改用图片或 JSON。

后续可扩展：图片诱导题、批量 CSV 映射导入、桌面编辑器、TextGrid 交换。线上发布、链接领取、身份服务和录音回传不属于当前实现。
